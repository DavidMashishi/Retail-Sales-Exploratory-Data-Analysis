## 📊 Project Overview

This project demonstrates a complete **Exploratory Data Analysis (EDA)** of a retail sales database using **Microsoft SQL Server and T-SQL**.

The objective was to transform raw transactional data into meaningful business insights by exploring:

- Customer purchasing behaviour
- Product performance
- Sales trends
- Revenue generation
- Operational performance

The analysis was performed entirely in SQL using relational database principles, including **joins, aggregate functions, window functions, subqueries, and date functions**.

The project follows a structured EDA workflow that progresses from understanding the database structure to identifying actionable insights that support business decision-making.

---

## 💼 Business Problem

Retail businesses generate thousands of transactions every day. Without proper analysis, decision-makers can struggle to understand business performance and identify opportunities for improvement.

This analysis addresses questions such as:

- Which products generate the highest revenue?
- Which customers contribute the most sales?
- Which product categories are underperforming?
- What are the major customer purchasing trends?
- How are sales distributed across countries?
- What is the overall business performance?

## 🎯 Business Questions

The analysis was designed to answer the following questions:

1. Which products generate the highest revenue?

# 🗄️ Dataset

The project uses a **Star Schema** consisting of:

- One fact table
- Two dimension tables

The database structure supports analysis across customers, products, sales transactions, geography, and product categories.

---

# 🗃️ Database Tables

The database consists of three related tables.

## 👥 Customers — `gold.dim_customers`

| Column | Description |
|---|---|
| `customer_key` | Unique key identifying each customer |
| `customer_id` | Original customer identifier from the source system |
| `customer_number` | Business customer reference number |
| `first_name` | Customer first name |
| `last_name` | Customer surname |
| `country` | Country where the customer resides |
| `marital_status` | Customer marital status |
| `gender` | Customer gender |
| `birthdate` | Customer date of birth |
| `create_date` | Date the customer record was created |

## 📦 Products — `gold.dim_products`

| Column | Description |
|---|---|
| `product_key` | Unique product identifier |
| `product_id` | Product ID from source system |
| `product_name` | Name of product |
| `category_id` | Product category identifier |
| `category` | Main product category |
| `subcategory` | Product subgroup |
| `maintenance` | Indicates whether maintenance is required |
| `cost` | Product acquisition cost |
| `product_line` | Product family or business line |
| `start_date` | Date the product became available |

## 🧾 Sales — `gold.fact_sales`

| Column | Description |
|---|---|
| `order_number` | Unique sales order number |
| `product_key` | Foreign key referencing the Products table |
| `customer_key` | Foreign key referencing the Customers table |
| `order_date` | Date the order was placed |
| `shipping_date` | Date the order was shipped |
| `sales_amount` | Total revenue generated by the transaction |
| `quantity` | Number of units sold |
| `price` | Selling price per unit |

# 🔍 Exploratory Data Analysis Workflow

The EDA process followed a structured analytical workflow:

**Database Exploration → Dimension Exploration → Date Exploration → KPI Measure Exploration → Magnitude Analysis → Top N / Bottom Analysis**

---

## 1. 🗄️ Database Exploration

The first stage focused on understanding the database structure.

Activities included:

- Exploring available tables
- Inspecting metadata
- Reviewing the database schema

---

## 2. 🌍 Dimension Exploration

The analysis explored key business dimensions, including:

- Customer countries
- Product categories
- Product hierarchy
- Product lines

This provided an understanding of the structure and distribution of the underlying business data.

---

## 3. 📅 Date Exploration

Date analysis was performed to understand the temporal characteristics of the dataset.

Key areas included:

- First order date
- Last order date
- Sales duration
- Youngest customer
- Oldest customer

---

## 4. 📊 KPI Measure Exploration

Core business KPIs were generated to establish an overall view of business performance.

### Core KPIs

- **Total Sales**
- **Total Orders**
- **Total Quantity Sold**
- **Average Selling Price**
- **Total Customers**
- **Total Products**

---

## 5. 📈 Magnitude Analysis

Magnitude analysis examined the scale and distribution of key business measures.

The analysis included:

- Customers by category
- Customers by gender
- Products by category
- Revenue by category
- Average cost by category
- Revenue by customer

---

## 6. 🏆 Top N & Bottom Analysis

The analysis identified the strongest and weakest performers.

### Analysis Areas

- Top 5 revenue-producing products
- Bottom-performing products
- Top 10 customers
- Lowest-ordering customers
- Best-performing product categories

This allowed the business to identify high-value opportunities as well as areas requiring further investigation.

---

# 🔑 Key Insights

The analysis produced several notable findings:

- **Bike** generated the highest overall revenue.
- **Mountain – 200 Series** was the highest-performing product line.
- **Female customers** generated slightly higher revenue than male customers.
- The **United States** represented the largest customer market by units sold.
- **Bike products** had the highest average production cost.
- **Racing Socks** generated the lowest revenue among all products.
- A relatively small number of customers contributed a significant portion of total revenue, highlighting opportunities for **customer segmentation and loyalty initiatives**.
